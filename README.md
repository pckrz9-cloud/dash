# Client Dashboard — AI Appointment Setter Stats

A multi-tenant dashboard for your agency's clients. Each client creates their
**own account** with an invite code you give them, connects their **own**
ManyChat, Instagram and Calendly credentials, and sees **only their own stats**
— refreshed automatically.

![Stack](https://img.shields.io/badge/stack-Next.js%2014%20·%20Prisma%20·%20NextAuth-blue)

## What each client sees

- **Instagram** — followers (with day-over-day change), daily reach, profile
  views, post count, plus a 90-day follower trend chart.
- **ManyChat** — connected bot/page, contact count where the ManyChat plan's
  API exposes it, with a trend chart.
- **Calendly** — every upcoming booked call: date, time, who booked, and a
  Join button for the meeting link.

Stats refresh automatically: the dashboard re-polls every minute, the server
re-syncs from the APIs when data is older than 10 minutes, and an optional
cron endpoint refreshes all clients in the background.

## Privacy model (how "each client only sees their own stats" is enforced)

- Signup requires a **one-time invite code** generated by you in `/admin` — no
  strangers can register.
- Every API route resolves the user from the **server-side session** and
  queries only that user's rows. There are no "get stats by id" endpoints.
- Clients get the `CLIENT` role; `/admin` and the admin APIs require `ADMIN`
  and return **no client stats** — only connection health.
- API keys are encrypted at rest (AES-256-GCM) and only ever returned masked
  (`••••1234`).
- All pages/APIs sit behind auth middleware; only login, signup and the
  secret-protected cron endpoint are public.

## Setup

```bash
# 1. Install
npm install

# 2. Configure
cp .env.example .env
#    - set NEXTAUTH_SECRET   (openssl rand -base64 32)
#    - set ENCRYPTION_KEY    (openssl rand -hex 32)
#    - set ADMIN_EMAIL / ADMIN_PASSWORD (your own login)
#    - set CRON_SECRET       (any random string)

# 3. Create the database + your admin account
npm run setup

# 4. Run
npm run dev        # development
npm run build && npm start   # production
```

## Onboarding a client (the whole flow)

1. Log in with your admin account → **Admin** → *Create invite code*.
2. Send the code to your client. They open `/signup`, enter it, and create
   their own account (email + password).
3. They land on **Settings** and paste their keys:
   - **ManyChat** — ManyChat → Settings → API → API key.
   - **Instagram** — a long-lived Graph API token with `instagram_basic` +
     `instagram_manage_insights`, plus their IG user ID (requires an
     Instagram professional account linked to a Facebook Page — you'll
     usually set this up together during onboarding).
   - **Calendly** — Calendly → Integrations → API & webhooks → personal
     access token.
4. "Save & test connections" syncs immediately and shows any credential
   problems inline. Done — their dashboard is live.

## Automatic background refresh (recommended)

The dashboard already refreshes itself while a client is looking at it. To
also keep stats warm (and build daily chart history) when nobody is logged
in, call the cron endpoint every 15–30 minutes from any scheduler:

```
GET /api/cron/sync
Authorization: Bearer <CRON_SECRET>
```

On **Vercel**, add to `vercel.json`:

```json
{ "crons": [{ "path": "/api/cron/sync", "schedule": "*/30 * * * *" }] }
```

(and set `CRON_SECRET` in the project env — Vercel Cron sends it
automatically as the Authorization bearer.)

Anywhere else, a crontab line works:

```
*/30 * * * * curl -s -H "Authorization: Bearer $CRON_SECRET" https://your-domain.com/api/cron/sync
```

## Notes & limits

- **ManyChat contact totals:** ManyChat's public API exposes rich account
  info but subscriber/contact totals only on some plans. The dashboard
  records the total whenever the API provides it and says so on the tile
  when it doesn't — everything else keeps working.
- **Instagram tokens expire.** Long-lived tokens last ~60 days; when one
  expires the client's dashboard shows a clear "Connection issue" banner and
  you'll see a ⚠ next to them in `/admin`. Paste a fresh token in Settings
  to fix.
- **Database:** SQLite out of the box (`prisma/dev.db`). For hosted
  deployments with a real database, switch the `provider` in
  `prisma/schema.prisma` to `postgresql` and point `DATABASE_URL` at it —
  no code changes needed. (Note: SQLite doesn't persist on serverless hosts
  like Vercel, so use Postgres there.)

## Project layout

```
prisma/schema.prisma        # Users, invites, credentials, snapshots, calls
src/lib/auth.ts             # NextAuth (credentials, JWT sessions, roles)
src/lib/crypto.ts           # AES-256-GCM for API keys at rest
src/lib/sync.ts             # Per-client sync engine (the tenant boundary)
src/lib/integrations/       # ManyChat / Instagram / Calendly API clients
src/app/api/                # Session-scoped API routes
src/app/(pages)             # /login /signup / (dashboard) /settings /admin
src/components/             # Stat tiles, trend charts, calls list, forms
src/middleware.ts           # Auth wall for everything non-public
```
